# API de desarrollo EHS México

Base `/api`, JSON UTF-8, misma procedencia que el frontend. No existen cuentas individuales ni separación de empresas; usar únicamente datos de demostración. El servidor de entrada `server/index.ts` puede exigir una contraseña compartida antes de la interfaz y la API, salvo `/api/health`; `createApp` por sí solo no añade esa protección. `createApp(db?, {ai?: boolean})` devuelve Express y expone `app.locals.db`. `createDatabase(path?)` usa `EHS_DB_PATH` o `data/ehs.sqlite`; `:memory:` está disponible para pruebas.

Las listas GET son arrays planos. POST devuelve el objeto creado y HTTP 201; PUT/PATCH devuelven el objeto actualizado y HTTP 200; DELETE devuelve HTTP 204. Los errores son `{error: string, details?: [{field, message}]}` con HTTP 400 (JSON o id inválido), 404, 409 (relación de datos), 413 (más de 1 MB) o 422 (validación). Los campos desconocidos se rechazan. Fechas ISO `YYYY-MM-DD` reales, puntuaciones numéricas, ids positivos.

## Aplicabilidad y fuentes

El catálogo en `catalog.ts` genera prioridades de revisión a partir del personal, las actividades declaradas y la ubicación. Las referencias federales, ambientales, de Jalisco y municipales están marcadas pendientes de cotejo. Los vínculos son portales oficiales de consulta, no artículos verificados. Cambiar el perfil filtra la lista sin borrar avance ni evidencia guardados.

La base inicial tiene seis personas ficticias, dos capacitaciones ficticias, dos análisis ilustrativos y un documento interno de demostración. No contiene legislación revisada ni citas legales inventadas. Los documentos internos, aunque revisados, nunca se usan para fundamentación normativa.

## Recuperación y generación opcional

La recuperación es local, por coincidencia de términos, sobre fragmentos de hasta 1,800 caracteres con 200 de solape. Solo participan documentos `kind:official`, `reviewed:true`, con URL gubernamental mexicana HTTPS. Devuelve hasta cuatro extractos originales. Sin coincidencias, informa insuficiencia de evidencia y no llama a IA.

Sin `EHS_AI_API_KEY`, la respuesta es explícitamente extractiva (`mode:retrieval`). Con esa variable, llama únicamente a `https://api.openai.com/v1/chat/completions` usando `EHS_AI_MODEL` (predeterminado `gpt-4.1-mini`), temperatura 0 y timeout de 20 segundos. Requiere acceso a `api.openai.com`; en el entorno administrado debe conservarse proxy y confianza TLS. Nunca se guarda la clave en la base ni se devuelve al cliente. No se envían trabajadores, perfil completo ni constancias: solo pregunta y extractos recuperados.

El modelo recibe instrucciones de usar solo el corpus y citar `[id]`. Se valida que los ids declarados y todos los `[n]` usados en la respuesta coincidan y pertenezcan al corpus. Esto no comprueba la veracidad ni la corrección de una interpretación. Fallas del proveedor, timeout, JSON o citas inválidos producen retorno a extractos con aviso, sin simular generación. Toda respuesta requiere revisión humana de autenticidad, alcance, vigencia y aplicación al caso.

## Validación

`npm test` ejecuta diez pruebas con SQLite en memoria y HTTP local efímero, además de persistencia en un directorio temporal y mocks de la API de IA. No utiliza claves reales ni solicitudes externas. `npm run typecheck` revisa tipos. Los tests cubren aplicabilidad y conservación de avance, integridad de participantes, edición de personas con historial, análisis HAZOP, restricciones de fuentes, recuperación en textos largos, errores, persistencia y rechazo de citas generativas ajenas al corpus.

Dos de estas pruebas verifican el acceso protegido del piloto: bloqueo de interfaz, recursos, API y escrituras sin credenciales, estado técnico público y validación de configuración.
